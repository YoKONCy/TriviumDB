## 五、DiskANN Rust 分析

DiskANN Rust 是本轮新增的最强外部图索引基线。它使用官方 Microsoft DiskANN Rust rewrite，在 Windows 上直接运行；数据为 Cohere-1M 全量构图、1000 query、top-10 ground truth。搜索参数 `Ls` 与 Python baseline 的 `ef` 使用相同扫描点：10/20/40/80/120/200/400/600/800。

### 最优同 Recall 插值结果

| Recall | DiskANN 最佳配置 | Ls 插值 | 1T-QPS | 8T-QPS | 1T lat(ms) | 8T lat(ms) | QuIVer 1T | QuIVer MT | **1T 倍数** | **MT 倍数** |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| ~95% | R=64 Lb=128 α=1.2 | ~21 | 2,975 | 11,557 | 0.34 | 0.63 | 3,555 | 36,729 | **1.2×** | **3.2×** |
| ~97% | R=64 Lb=128 α=1.2 | ~36 | 2,085 | 8,047 | 0.50 | 0.92 | 2,140 | 21,021 | **1.0×** | **2.6×** |
| ~99% | R=64 Lb=128 α=1.2 | ~98 | 879 | 3,538 | 1.18 | 2.15 | 1,182 | 11,837 | **1.3×** | **3.3×** |
| ~99.5% | R=64 Lb=128 α=1.2 | ~157 | 585 | 2,433 | 1.79 | 3.26 | 644 | 6,032 | **1.1×** | **2.5×** |

### 关键观察

1. **DiskANN 1T 非常强**：在 97% recall 附近几乎追平 QuIVer，说明官方 DiskANN 的单线程图搜索实现质量很高。
2. **DiskANN MT 扩展明显弱于 QuIVer**：同 Recall 下 QuIVer 仍有 2.5-3.3× MT-QPS 优势，说明 QuIVer 的紧凑热数据路径和低内存带宽压力在并发下更有效。
3. **DiskANN 高精度依赖更重构图**：最优结果全部来自 `R=64, L-build=128, α=1.2`，构图耗时 396.2s，约为 QuIVer 93s 的 4.3×。
4. **DiskANN 是最可信的强基线**：相比 hnswlib/FAISS/USearch，它在 1T 下更接近 QuIVer，因此论文中可以单独强调 QuIVer 仍在 MT 生产负载下显著领先 DiskANN。

## 七、QuIVer 优势分析

### 为什么 MT 倍数 >> 1T 倍数？

| 因素 | QuIVer | HNSW / DiskANN 系 |
|---|---|---|
| 热数据大小 | **675 MB**（BQ签名+邻接） | **3.2 GB+**（f32向量+邻接） |
| 16线程 L3 争用 | 低（16MB L3 可缓存大部分热路径） | 高（3.2GB 远超 L3） |
| 每查询分配 | **零**（thread_local Bitset 复用） | 每查询分配 visited set |
| 每跳数据量 | 192B BQ签名 + 260B邻接 | 3072B f32向量 + 260B邻接 |
| Prefetch 效果 | 高（数据紧凑，2条 cache line） | 低（数据散布，48条 cache line） |

### QuIVer 当前查询阶段耗时拆解

基于 Cohere-1M、768-d、top-10、m=32、ef_c=128 的阶段 profiling，QuIVer 查询时间主要集中在 layer0 BQ beam search。典型旧路径 `cosine ef64 prefetch` 的单 query 平均耗时如下：

| 阶段 | 平均耗时 | 占比 | 说明 |
|---|---:|---:|---|
| encode | 4.97 μs | 1.7% | query 编码成 2-bit BQ 签名 |
| upper | 0.03 μs | <0.1% | 上层 greedy descent，基本可忽略 |
| beam | 260.79 μs | 86.8% | layer0 BQ beam search，当前最大瓶颈 |
| rerank | 33.30 μs | 11.1% | f32 cosine 精排 |
| sort | 0.87 μs | 0.3% | top-k 排序 |
| total | 300.56 μs | 100% | 单线程平均延迟 |

后续消融进一步确认：瓶颈不是 encode、upper、sort，也不是 f32 rerank，而是 layer0 beam 内部的大量随机 BQ distance 计算与邻接扩展。以 ef128/rerank48 的完整优化路径为例，`cheap beam -> real BQ reorder -> f32 rerank` 中 real BQ reorder 仅约 4.3 μs，占总耗时约 1%，单独优化意义很小；它的价值在于让 cheap beam 的候选顺序更接近真实 BQ 排序，从而维持 recall。

当前已经完成的核心优化包括：

1. **cheap distance beam**：用 `popcnt(pos xor q_pos) + popcnt(strong xor q_strong)` 替代完整 weighted BQ distance 做 layer0 导航。
2. **real BQ reorder**：cheap beam 产出 ef 候选后，用完整 weighted BQ distance 对候选重排，再进入 f32 rerank。
3. **dim=768 专用 AVX512 cheap fast path**：针对 Cohere-1M 固定 12 个 u64 chunk 的情况，去掉通用 loop/remainder 分支，直接使用 512-bit + 256-bit load、xor、vpopcnt、reduce。
4. **prefetch 保留**：邻居展开前预取 BQ signature，对 beam search 有稳定收益。

优化后的标准 MT 复测显示，`ef=64` 从 36,729 QPS 提升到 43,103 QPS，约 **+17.4%**；单次复测最高记录为 44,384 QPS，约 **+20.8%**。`ef=128` 从 21,021 QPS 提升到 22,309 QPS，约 **+6.1%**。因此 P0/P1 的实际收益主要集中在 95% recall 档，97% recall 档收益较小。

下一步中高收益方向应继续围绕 layer0 beam，而不是 reorder：

| 方向 | 预期收益 | 原因 |
|---|---|---|
| 减少 beam visited 数 | 高 | ef128 仍会访问约 4k 节点，少访问 10%-20% 就可能明显降低总耗时 |
| 批量计算邻居 cheap distance | 中高 | 当前仍是逐个 `distance_to_sig_cheap(nb)`，可尝试合并多个邻居的 load/popcnt/score |
| graph / BQ store 局部性重排 | 中高 | beam 是随机访存主导，节点重排可能降低 cache miss 与 TLB 压力 |
| 邻接与签名联合预取策略 | 中 | 现有只预取 BQ signature，可继续研究邻接展开时的批量预取 |
| 继续微调 cheap kernel | 中 | P1 已做 768 专用 AVX512，后续收益可能低于访问次数与局部性优化 |
| 单独优化 real BQ reorder | 低 | reorder 约 4 μs，占比约 1%，不是主要瓶颈 |
