# TriviumDB 0.8.10

本版本改进 QuIVer 构图连通性、发布中断恢复和 TQL 解析防护，并增加 WebUI 图探索与 AI 辅助功能。

## 本次变更

- **TQL 递归防护**：标量表达式与现有嵌套解析共用 128 层预算，覆盖括号、函数参数、一元运算和嵌套子查询，超限返回解析错误；保留原 fuzz 样本和回归测试。
- **QuIVer 构图连通性**：最终剪枝在同签名近邻挤占时保留其他签名候选，构图收尾连接入口不可达区域。增量剪枝保留导航树，入口升层连接旧树；父节点和遍历工作区纳入热内存或构建峰值预算。
- **旧索引处理**：通过重建应用新构图规则。有效图重载保持邻接表逐边不变，仅恢复运行期状态；断连图返回需要重建的错误，数据库沿用既有重建/拒绝策略。`.quiver` 格式仍为 v1。
- **测试执行范围**：多平台 CI、发布验收与覆盖率任务显式启用 `test-hooks`，覆盖确定性交错、物理策略差分、定点 I/O 故障和发布阶段强杀。独立 TSan/Miri 任务补充 ASan；Windows 故障任务遇到原生命令失败时立即报错。
- **发布中断恢复**：Mmap 写新事实前持久化旧代独立备份与 `TPUB` v1 撤销日志；可写打开先恢复未提交发布，再回放 WAL，已提交的新 marker 不回滚。支持首次 flush、追加、更新/删除/compaction 与恢复途中再次中断；同一句柄失败重试保留原始备份。主文件 v9、marker v3 不变；备份增加旧主文件与向量文件大小对应的磁盘读写和临时空间。
- **恢复断言与默认入口**：发布强杀验收要求完整恢复；18 组强杀场景覆盖 2048×65 数据，逐项验证已同步节点、向量、Payload 和更新边，再次持久化重开。默认测试增加独立日志 oracle、损坏备份/提交点/只读零写验证；unsafe 损坏输入断言要求结构化错误。本地 `cargo test-critical` 包含关键 hook 套件与全部 query 测试。
- **CI 基准修复**：`ci_report` 的读取查询使用 `tql()`，修复旧 `tql_mut(read query)` 被拒绝导致的手动基准任务失败。变异测试与覆盖率门禁策略维持原状。
- **WebUI 探索与 AI 辅助**：合入 [PR #63](https://github.com/YoKONCy/TriviumDB/pull/63) 的邻域扩展、路径探索、星云模式与 AI Copilot。图边只采用服务端明确返回的边，按方向与标签保留平行边、权重和元数据；增量扩展沿用默认 1500 节点渲染上限，路径取回保留完整 `u64` ID，失败与截断明确提示。
- **WebUI 验收修复**：自检增至 124 项；Chromium/WebKit 使用真实 Server 与独立临时库，测试脚本只清理自己创建的进程和文件。Windows CI 对已有七张 Win32 基线执行实际比较，缺失基线或依赖时报错，截图与差异图始终上传；详见 [WebUI 测试指南](../webui-testing.md)。
- **文档与元数据**：同步 Rust Core、CLI、Server、Python、Node、锁文件及控制台版本显示，更新架构、迁移、预算和 unsafe 验证边界。

## 索引升级与查询行为

旧索引应重新构建以采用本次构图规则。入口全可达表示拓扑可遍历全库；实际召回率取决于 `ef`、精排预算和数据分布。[连通性基准](../../benches/bench_quiver_connectivity.rs)覆盖七组合成数据、四个查询宽度及 Recall、QPS、延迟和热内存；低内在维度数据仍可能需要更大的搜索宽度。

> **评估提醒**：真实百万规模场景需使用对应数据集单独测量。

默认查询使用无训练 SM-L2 导航与原始向量余弦精排，详见 [QuIVer 架构说明](../quiver.md)。

## 测试

本版本记录的验收包括多平台读写、发布中断恢复、确定性并发交错、差分验证及 ASan/TSan/Miri 专项检查。
