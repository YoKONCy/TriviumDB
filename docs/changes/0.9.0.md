# TriviumDB 0.9.0

## 中文说明

`0.9.0` 是正式版，汇总 `0.9.0-beta.1` 至 `beta.4` 的嵌入式资源管理、事务与恢复、类型化存储、统一查询及跨语言契约，并增加嵌入式 Console 宿主协议、迁移发布和 Windows 打开竞态修复。Rust Embedded Core 仍是存储、事务、查询与生命周期语义的唯一实现来源。

### 版本、安装与通道

| 制品 | 正式版元数据与通道 |
| --- | --- |
| Rust crate | `triviumdb = "0.9.0"`，crates.io 正式版本 |
| Python | `triviumdb==0.9.0`，PyPI 正式版本，Python 3.9–3.12 |
| Node.js | `triviumdb@0.9.0`，npm `latest` 通道 |
| CLI、Server 源码 | `0.9.0`；Server 与 WebUI 继续采用 nightly 开发与兼容性边界 |
| Git Tag | `v0.9.0`，指向已验收的 `dev → master` Release 合并提交 |

```bash
pip install "triviumdb==0.9.0"
npm install triviumdb@0.9.0
cargo add triviumdb@0.9.0
```

从 Beta 切换到正式版时显式指定上述版本。npm 的历史 `beta` 标签与既有预发布包保持不变；正式版通过 `latest` 分发。实际上传与公开可见状态以对应注册中心和发布工作流结果为准。

### 原生三模查询、事务与数值语义

- Rust、Python、Node 与 CLI 共用向量、属性图和 JSON 文档内核。TQL 由 Cascades 统一规划，支持参数化 Prepared 查询、标量与容器投影、聚合、路径、图算法及向量/图组合查询；返回、绑定、别名、排序和行预算保持同一语义。
- 事务按操作顺序维护节点存在状态，统一执行插入、更新、删除和边操作。唯一约束按事务最终状态判断，支持合法键交换；预检拒绝不会留下首条操作、消耗提交后的 ID 或写入部分 WAL。
- WAL 追加、flush 或同步失败后隔离 writer；应用阶段异常同时隔离实例与已准入的共享查询，避免读取部分事务状态。重开依照真实提交边界恢复，异常展开恢复 QuIVer 暂停状态。传输失败或返回错误不能作为写入已回滚的证明，应用应按业务标识查询确认。
- Payload CRUD、事务与 `$inc` 保留可表示整数的精度，溢出、非法类型及非有限数值在写入前拒绝。数值索引和 TQL 的整数/浮点比较覆盖大整数、负数、浮点零和精确范围边界。
- MATCH 保留平行边的行重数，单跳双向自环计一次；图模式和可变长路径使用有界显式栈，统一计量探索、扫描和回溯，并检查取消与期限。维度和有限值校验覆盖普通、精确及 GraphFirst 检索。
- 浮点余弦遇到范数、点积或分母上溢/下溢时使用 `f64` 累加，常规有限幅值仍沿用既有 SIMD 路径。`u64` 检索保留二进制位模式并按汉明匹配计分，不自动采用浮点 QuIVer；默认 SM-L2 导航和余弦精排算法未在本次正式版准备中替换。

### 多实例资源、关闭与文件锁

- `ResourceRuntime` 统一管理多实例声明配额、临时工作区、线程和任务名额，保护维护预算。读取物化、图遍历、索引构建与加载在分配前进行实例和共享预算准入，拒绝后归还额度并保留原事实；诊断接口区分实例估算、配额及关闭阶段。
- 受控关闭先阻止新操作，再排空真实在途任务、完成持久化、释放映射、Hook、文件句柄与配额。成功关闭后，即使调用方继续持有 Database、Prepared、查询结果或控制台对象，也可移动文件组和重新打开。关闭失败保留锁、状态与恢复依据，处理原因后可重试。
- Python 上下文管理和 Node `close`、`dispose`、资源管理及工作线程退出复用内核生命周期；等待超时结束等待，不取消正在执行的持久化，也不提前归还文件锁。
- 修复后台关闭发布与另一个打开入口的路径竞态：Windows 原子替换期间，句柄可能解析到 NTFS 已删除文件。现在校验调用路径与规范路径的文件身份，避免据此派生错误锁路径。预检失败后仅核对已有协调文件；真实租约冲突返回 `TDB_DATABASE_LOCKED`，租约已释放时持锁重新解析并验证协调文件身份，再将同一租约交给新实例。
- 持续缺失、访问失败或身份不匹配仍返回错误；失败路径不创建新库或协调文件。ReadOnly 保持物理零写，Immutable 不参与租约探测。Unix 符号链接不能把别名的空闲协调文件当作目标数据库的租约。

### 类型化存储、派生索引与恢复

- 主文件 `.tdb` v10 保存 dtype、元素宽度和头部 CRC。新库在接收 WAL 前先建立类型检查点；错误 dtype 在写入前拒绝，Rom/Mmap 检查精确向量块长度。打开时对节点、向量、Payload、图、索引与 WAL 解码执行峰值准入，成功后才进行允许的迁移或 WAL 尾部截断。
- Mmap 的 `.flush_ok` v3 将 `.tdb`、`.vec` 与 generation 化 `.pld` 绑定，撤销日志和旧代备份支持中断恢复；完整坏 WAL 帧返回 `CorruptedFile` 并保留日志，物理截断尾部和无提交封条事务按完成的提交边界恢复。恢复过程支持再次中断及同句柄失败重试。
- `.pidx` v8 用无歧义的 JSON 字符串数组编码复合字段，保留 NUL、转义和 Unicode。唯一约束发布失败隔离实例，重开按提交点采用正确定义并回放 WAL；历史复合 posting 可回退到事实扫描，普通复合索引可按原字段列表重建。
- `.quiver.meta` v2 校验主数据、向量、索引 CRC 和完整 ID/slot 关系。历史元数据按 `MissingIndexPolicy` 回退或拒绝；只读回退保留原件。图副本完整验证端点、平行标签、自环、权重与 Metadata，校验与解码峰值参与预算。
- Windows 向量替换或重映射失败导致当前映射失效时，实例和共享句柄进入待恢复状态，保留原 I/O 错误及 WAL，释放后重新打开恢复。
- 文本正文登记采用替换语义，空正文清除 BM25 内容，节点删除清理正文与关键词；延期加载时普通保存保留旧文本文件，显式修改后合并。文本登记仍不属于事务 WAL 操作，应用须保留权威正文和可重建来源。

### 维度迁移与不可变代际

- 维度迁移先构建独占暂存库，再以不覆盖目标的原子重命名发布文件组，替代 Beta.4 的暂存到目标硬链接。首文件发布后、提交前与提交后强杀均按发布日志处理：提交前回滚本次目标，提交后保留完整新库，源库保持原样。
- 发布在提交点前后同步相关目录，文件系统必须支持排他原子重命名；不支持时返回 I/O 错误。已有主文件、侧文件或按实际文件系统规则构成的大小写别名，在创建目标租约、暂存库和发布日志前拒绝；Unix 还保留非 UTF-8 侧文件并拒绝悬空主文件链接。
- `GenerationStore` 固定规范根路径与运行目录，跨实例、跨进程 Reader 使用共享租约保护旧代回收。只读制品目录不写入运行租约；所有协作进程须使用一致的根路径和可写运行目录。

### 嵌入式 Console v1

- 新增 Rust `ConsoleSession`、`ConsoleHost`、`Database::console_request`，Python `db.console_request(session, request_json)` 与 Node `db.consoleRequest(session, requestJson)`。JSON 字符串请求共用查询、向量/图、索引、原子事务和批量导入语义，直接复用已经打开的实例。
- 会话默认只读，绑定具体实例身份，不能复用到同路径的新实例。Rust 适配器仅保存弱引用，业务与 Console 使用同一个 Mutex；竞争或重入立即返回 `WouldBlock`。detach 只停止入口并发出协作取消，不关闭宿主数据库；Python 保持原生独占借用，Node 公共加载器阻止 Console 与业务 Hook 双向重入。
- 会话设置功能入口、请求/响应字节、操作数、工作集及 deadline 边界；功能开关不构成 TQL 数据权限沙箱。写计划及确认响应在 WAL 前准入，响应缓冲参与共享工作区预算并跨提交保留额度。提交开始后，取消、超时或断线不撤销事务。
- 显式节点 ID 与 `u64` 向量分量使用十进制字符串。f32/f16 入站复用内核 f32 转换，出站返回实际数值；Payload JSON 类型不变，包含大整数的 Payload/参数需要宿主采用无损编解码。原有 Node 数值 ID API 和页面写入仍限制在 JavaScript 安全整数范围。
- nightly Server crate 提供可嵌套的 HTTP Router，复用现有 ConsoleHost，不重新打开路径、不创建 Writer Actor，也不接管监听或关闭。并发许可在读取请求体前取得，保留至真实 blocking 工作结束；读取与执行共享 deadline，网络发送不持数据库互斥锁。
- 原样资源包包含 HTML、版本化协议、manifest、接入文档及许可证。现有 HTML 仍使用 Server HTTP v1，前端负责人须适配 Console RPC v1；manifest 明确说明该条件及现有 CDN 依赖。本期不提供完整离线挂载、交互式事务、OCC、幂等缓存或 NDJSON 流式 Console 协议。详见[宿主接入](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/docs/embedded-console.md)。

```bash
python scripts/package_console.py --output .tmp/console/triviumdb-console.zip
```

- V4 Web Console 提供明暗主题、查询标签、结果编辑与批量操作、事务暂存、CSV/JSONL 导入、图探索和向量实验台。Server 为页面提供 gzip 和弱 ETag，并统一非法查询参数的结构化错误；读 TQL 可经 `mutation=true` 进入读路径。

- 页面编辑、删除和导入在发送或暂存前验证安全整数 ID，避免相邻节点误写。提交期间新增操作保留到下一批，失败重试保留原顺序；切换/关闭查询标签取消旧查询，迟到 JSON/NDJSON 结果不能覆盖其他标签。
- Server 与 WebUI 仍为 nightly 预览，不因源码及附件版本号为 `0.9.0` 而获得正式协议兼容承诺。浏览器、视觉和交互诊断保持独立手动工作流。
- Rust、Python 和 Node 保留统一结构化错误码与必要详情；Python 存根和 npm 公共声明随接口交付，Node 大整数错误字段可为 `number | string`。npm 构建保留维护的公共加载器。
- 正式 Tag 必须位于已合并的同仓库 `dev → master` Release PR 的合并提交，并通过同提交 master CI。GitHub Release 正文读取本文件的完整双语说明；npm/PyPI 摘要分别报告实际成功、失败、取消、既有版本跳过和上游阻断，上传完成与注册中心公开可见状态分别核对。

### 升级、兼容与验收条件

1. 停止现有实例，保存完整目录快照或全部文件组，再用新版本打开。Rom 主数据和向量位于 `.tdb`；Mmap 使用 `.vec` 与 generation 化 Payload 文件，WAL、文本和索引文件按实际配置保留。不要只复制正在写入的主文件。
2. 从 Beta.4 升级不新增磁盘格式迁移。历史非空 v5–v9 检查点按几何校验；仅 WAL 或无类型空检查点附带日志的旧样本，应先用原版本恢复并完成检查点。新格式降级使用升级前的完整备份。
3. 升级跨进程 Reader 回收协议前先结束旧 Reader，保持规范根路径、运行目录和 Reader 存活期间的根位置一致。历史 `.pidx`、`.quiver.meta` 与图副本的兼容、回退和重建按上述策略执行。
4. Rust 低层 BQ 距离、签名和原始存储构造 API 使用 `Result`，调用方传播错误；穷尽匹配覆盖新增 Prepared 参数、预算和 Console 错误变体。Python 与 Node 保留各语言命名及返回包装，按错误码和字段控制流程。
5. 已验收的功能源码覆盖 Linux/Windows/macOS、x86_64/ARM64、QEMU、真实 wheel/npm 包、类型消费、受控并发与故障恢复，以及 ASan、TSan、Miri 和短时 fuzz 的实际配置范围。Windows 另执行 debug 1000 次与 release 500 次工作线程退出重开。正式发布提交及各平台制品结果以 `v0.9.0` 对应 CI/CD 记录为准；手动基准和突变测试不作为已运行项目。详见[测试实践](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/docs/testing.md)、[公共 API](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/docs/api-reference.md)、[生命周期与快照](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0/docs/lifecycle-snapshots.md)。

## English release notes

`0.9.0` is the stable release. It consolidates embedded resource management, transactions and recovery, typed storage, unified queries and cross-language contracts from `0.9.0-beta.1` through `beta.4`, and adds the embedded Console host protocol, safer migration publication and Windows opening-race fixes. Rust Embedded Core remains the single implementation authority for storage, transactions, queries and lifecycle semantics.

### Versions, installation and channels

Rust crate, CLI and Server source, npm and Python package metadata all use `0.9.0`; the tag is `v0.9.0`. Python supports 3.9–3.12. Use `pip install "triviumdb==0.9.0"`, `npm install triviumdb@0.9.0` or `cargo add triviumdb@0.9.0`. The stable npm package uses `latest`; existing `beta` tags and prerelease packages remain unchanged. Server and WebUI retain their nightly development and compatibility boundaries. Actual upload and public availability are determined separately from the corresponding registry and publishing workflow results.

### Native tri-model queries, transactions and numerics

- Rust, Python, Node and CLI share the vector, property-graph and JSON-document core. Cascades plans TQL, including parameterized Prepared queries, scalar/container projections, aggregation, paths, graph algorithms and vector/graph composition. Results, bindings, aliases, sorting and row budgets follow the same semantics.
- Transactions maintain node existence in operation order and execute inserts, updates, deletes and edges through one implementation. Unique constraints evaluate final transaction state, allowing valid key exchanges. Preflight rejection leaves no first operation, committed ID allocation or partial WAL write.
- WAL append, flush or synchronization failures isolate the writer. Application failures also isolate the instance and already-admitted shared queries from partial transaction state. Reopening follows actual commit boundaries; unwinding restores QuIVer suspension state. A transport failure or error response does not establish rollback: applications should query by business identity to confirm facts.
- Payload CRUD, transactions and `$inc` preserve representable integer precision; overflow, invalid types and nonfinite values are rejected before writing. Numeric indexes and TQL integer/float comparisons cover large integers, negative values, floating zero and exact range boundaries.
- MATCH preserves parallel-edge multiplicity and counts a bidirectional single-hop self-loop once. Graph patterns and variable-length paths use bounded explicit stacks, account for exploration, scans and backtracking, and check cancellation/deadlines. Ordinary, exact and GraphFirst retrieval share dimension and finite-value validation.
- Floating cosine uses `f64` accumulation when norms, dot products or denominators overflow/underflow, while ordinary finite magnitudes retain existing SIMD paths. `u64` retrieval preserves binary patterns and Hamming-match scoring without automatically adopting floating QuIVer. Stable-release preparation does not replace default SM-L2 navigation or cosine reranking.

### Multi-instance resources, shutdown and file locks

- `ResourceRuntime` manages database reservations, temporary workspace, threads and task slots across instances while protecting maintenance capacity. Read materialization, graph traversal, index construction and loading admit instance/shared budgets before allocation; rejection releases reservations and preserves existing facts. Diagnostics distinguish memory estimates, reservations and shutdown stages.
- Controlled shutdown stops new operations, drains actual in-flight work, persists data, and releases mappings, Hooks, handles and reservations. Successful close permits file-group moves and reopening even while callers retain Database, Prepared, result or Console objects. Failed close retains the lock, state and recovery evidence for retry after the cause is resolved.
- Python contexts and Node close/dispose, resource management and worker termination use the core lifecycle. Waiting timeouts end the wait without cancelling persistence or releasing the file lock early.
- Fixed an opening race with background-close publication: atomic Windows replacement can resolve a handle to an NTFS deleted-file path. Requested/canonical file identity is now checked before deriving a lock path. Failed preflight checks only an existing coordination file; actual contention returns `TDB_DATABASE_LOCKED`. If the lease has become available, the opener resolves the path under it, verifies coordination-file identity and transfers that same lease to the new instance.
- Persistent absence, access failure or identity mismatch remains an error. Failure paths create neither a new database nor coordination file. ReadOnly preserves physical zero-write behavior; Immutable does not probe leases. Unix symbolic links cannot substitute an idle alias coordination file for the target database's lease.

### Typed storage, derived indexes and recovery

- The v10 `.tdb` header persists dtype, element width and CRC. New databases establish a typed checkpoint before accepting WAL. Wrong dtypes are rejected before writing; Rom/Mmap validate exact vector-block length. Opening admits peak node/vector/Payload/graph/index/WAL decoding capacity before permitted migration or WAL-tail truncation.
- Mmap `.flush_ok` v3 binds `.tdb`, `.vec` and generation-scoped `.pld` files. Undo journals and prior-generation backups recover interrupted publication. Complete corrupt WAL frames return `CorruptedFile` while preserving the log; physically incomplete tails and transactions without commit seals recover to completed commit boundaries. Recovery supports further interruptions and retry on the same handle.
- `.pidx` v8 encodes composite fields as unambiguous JSON string arrays, preserving NUL, escapes and Unicode. Failed unique-schema publication isolates the instance; reopening adopts definitions according to the commit point and replays WAL. Legacy composite postings can scan authoritative facts; recreate ordinary composite indexes using their original field lists.
- `.quiver.meta` v2 checks main/vector/index CRCs and complete ID/slot relationships. Legacy metadata follows `MissingIndexPolicy` fallback/error behavior; read-only fallback preserves originals. Graph copies validate endpoints, parallel labels, self-loops, weights and Metadata, with validation/decoding peaks admitted against budgets.
- Failed Windows vector replacement/remapping that invalidates the current mapping moves the instance and shared handles into a recovery-required state, preserving the original I/O error and WAL for reopening after release.
- Text registration replaces document content; empty text clears BM25 content and node deletion removes text/keywords. Deferred loading preserves prior text files during ordinary saves and merges explicit changes. Text registration remains outside transactional WAL operations; applications must retain authoritative, rebuildable text sources.

### Dimension migration and immutable generations

- Dimension migration builds an exclusive staging database and publishes its file group with non-overwriting atomic renames, replacing Beta.4's staging-to-destination hard links. Forced termination after the first file, before commit or after commit follows the publication journal: pre-commit destinations roll back, committed destinations remain complete, and sources remain unchanged.
- Publication synchronizes relevant directories around commit. Filesystems must support exclusive atomic renaming; unsupported operations return I/O errors. Existing main files, sidecars and case aliases under actual filesystem rules are rejected before creating destination leases, staging or journals. Unix checks also preserve non-UTF-8 sidecars and reject dangling main-file links.
- `GenerationStore` fixes canonical root/runtime directories; shared cross-instance and cross-process Reader leases protect old-generation reclamation. Runtime leases do not write into read-only artifact directories. Cooperating processes must share consistent roots and a writable runtime directory.

### Embedded Console v1

- Added Rust `ConsoleSession`, `ConsoleHost`, `Database::console_request`, Python `db.console_request(session, request_json)` and Node `db.consoleRequest(session, requestJson)`. JSON-string requests share query, vector/graph, index, atomic transaction and batch-import semantics on an already-open instance.
- Sessions default to read-only and bind to a specific instance, preventing reuse against a replacement at the same path. The Rust adapter holds only a weak reference; host and Console share one Mutex, and contention/reentry returns `WouldBlock` immediately. Detach stops entry and requests cooperative cancellation without closing the host database. Python retains exclusive native borrowing; the public Node loader blocks Console/host Hook reentry in both directions.
- Host policy controls operation entry points, request/response bytes, operation counts, working sets and deadlines. Feature switches are not a TQL data-permission sandbox. Write plans and acknowledgement responses are admitted before WAL; response buffers reserve shared workspace across commit. Cancellation, timeout or disconnection after commit starts does not undo a transaction.
- Explicit node IDs and `u64` vector components use decimal strings. f32/f16 input uses the core f32 conversion path and output returns actual numeric values. Payload JSON types remain unchanged; large-integer Payload/parameters require lossless host codecs. Existing numeric Node ID APIs and page writes retain JavaScript safe-integer limits.
- The nightly Server crate adds a nestable HTTP Router over the same ConsoleHost, without reopening paths, creating a Writer Actor or owning listening/shutdown. Concurrency admission precedes body reading and lasts until actual blocking work ends. Body reading and execution share a deadline; network transmission does not hold the database mutex.
- The unmodified resource bundle contains HTML, versioned protocol, manifest, integration guide and license. Existing HTML still uses Server HTTP v1 and needs frontend-owned Console RPC v1 adaptation; the manifest declares that requirement and CDN dependencies. ### Upgrade, compatibility and validation conditions

1. Stop existing instances and back up a complete directory snapshot or file group before opening with the new version. Rom keeps main data/vectors in `.tdb`; Mmap uses `.vec` and generation-scoped Payload files. Preserve WAL, text and indexes as configured; copying only a live writable main file is insufficient.
2. Upgrading from Beta.4 introduces no additional disk-format migration. Historical nonempty v5–v9 checkpoints are validated by geometry. Recover WAL-only or untyped-empty-checkpoint samples with logs using the original version, then complete a checkpoint. Downgrades use the full pre-upgrade backup.
3. Retire old Readers before upgrading cross-process reclamation. Keep canonical roots, runtime directories and root location stable for live Readers. Apply the `.pidx`, `.quiver.meta` and graph-copy compatibility, fallback and rebuild policies above.
4. Low-level Rust BQ distance, signature and raw-storage construction APIs return `Result`; callers propagate errors. Exhaustive error matches include new Prepared-parameter, budget and Console variants. Python/Node retain language-specific names/result wrappers; control flow should use error codes and fields.
5. Validated feature-source coverage includes Linux/Windows/macOS, x86_64/ARM64, QEMU, installed wheel/npm packages, type consumers, controlled concurrency/recovery, and the actual ASan/TSan/Miri/short-fuzz configurations. Windows additionally completed 1000 debug and 500 release worker-exit/reopen iterations. Final release-commit and platform-artifact outcomes are determined by the CI/CD runs for `v0.9.0`; manual benchmark and mutation jobs are not claimed as executed.
