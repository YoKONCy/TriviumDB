# TriviumDB 0.8.11

本版本减少向量存储的冗余分配，并修复文本索引在更新、删除和延期加载时的生命周期问题。

## 向量存储

- 普通查询、保存和重开不再为每个节点物化历史 `BqSignature` 数组；新快照仅保留原格式允许的 16 字节空 `TBQF` 缓存头，省去每个 slot 的 384 字节旧缓存。显式调用旧 Rust 整库签名接口时仍可按需生成，容量计入内存估算。
- 精确扫描直接读取 mmap 基础层与内存增量层，避免为查询合并整库向量。连续视图仅在显式请求时生成，写入后释放失效副本；Rom 保存逐段输出向量。
- 主文件仍为 v9，保留历史 BQ 缓存块的格式校验和兼容读取。QuIVer 的 BQ2、SM 位码、构图和导航算法沿用上一版本实现，已有 QuIVer 索引可继续使用。

## 文本索引

- 默认 `load_text_index=false` 时，纯向量写入、`flush()` 和 `close()` 保留已有 `.text` 文件。显式文本写入或预热会先加载旧索引，再合并修改；损坏文件、元数据写入失败和预算不足会返回错误。
- `index_text(id, text)` 替换该节点的旧正文与词频；空字符串清除 BM25 正文，保留显式关键词。多字段或多段正文需要拼接后一次登记。Payload 与显式登记的正文分别更新。
- 删除节点时清理正文、关键词和统计，覆盖事务删除与 WAL 删除回放；复用的 NodeId 以空文本状态开始。稀疏候选在 Top-K 截断前验证节点存活与 Payload 谓词。
- 同一节点重复注册规范化后的关键词保持幂等。关键词变化后，首次查询按需编译 AC 自动机；`build_text_index()` 可提前预热，构建错误同步返回 Rust、Python 与 Node 调用方。
- 文本延期加载和待处理删除计入内存预算；需要预留的删除工作区在写 WAL 前检查。ReadOnly/Immutable 保持物理零写。

## 升级与能力边界

`.text` 仍为 TIDX v2，元数据仍为 TMET v1，无需格式迁移。历史重复关键词在加载时规范化；独立历史快照 fixture 验证兼容性。

本版本的文本登记通过 `flush()` 或可写句柄的 `close()` 持久化；`Transaction` WAL 保存节点、向量、Payload 和业务边。

> **恢复提醒**：本版本中正文与事实数据的跨文件提交缺少完整原子性保证。应用应保留权威正文和别名来源；旧版本已覆盖的文本内容需要从该来源重建。

属性索引的字段范围为顶层标量。N-gram 索引仍要求至少三个字符；两字中文可使用 BM25，`CONTAINS` 可通过扫描回退验证完整谓词。

## 验证

新增文本生命周期回归覆盖 Rom/Mmap 保存、故障重试、损坏输入拒绝、预算拒绝、删除后 ID 复用、只读零写及跨版本快照。BM25 使用独立词袋 reference 校验分数，Rust/Python/Node 复用共享 JSON 契约；向量存储使用独立序列化 oracle 和并发视图验证。执行方法见[测试实践](../testing.md)。
