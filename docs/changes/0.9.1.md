### 文档身份、结构与证据

- 文档根保存来源身份、正文、摘要及修订，结构清单记录词、行、段落等逻辑块的 UTF-8 范围、父级与可选节点表示。纯结构节点支持省略向量，具有向量的表示复用数据库维度及 dtype。
- 原子文档写入统一安装根、表示节点及结构边，校验所有权、范围、父子关系和预期修订。替换、删除及恢复沿现有事务、WAL 和文件组发布语义执行，条件冲突通过结构化错误返回。
- 整篇与片段分别维护 BM25 语料，按来源分组后稳定截断。查询支持块类型字段权重、根与片段元数据过滤、数组成员交并集及来源限制，返回来源修订、命中排名、原文字节和行列证据。
- 位置索引提供词项、短语和有序邻近查询，采用 `tdb-text-ascii-cjk2-v1` 分析器。重复词、中文双字重叠、Unicode 大小写及跨行范围通过同一位置契约解释。
- 上下文请求在同一读视图内核对引用修订，展开邻居和纯目录祖先，并合并相接或重叠范围。派生索引按需构建，事实变化后失效，工作区、位置访问及输出执行预算与取消检查。

完整契约见[文档来源与结构](../documents.md)。

### 自动解析、原文回映射与分批发布

- 内置纯文本、Markdown、HTML、JSON／JSONL 解析，按显式格式、媒体类型或扩展名选择解析器，生成稳定配置身份及带 UTF-8 范围的逻辑块，支持有界叶块拆分和可选行子块。
- 解析文本及来源文本分别保存 SHA-256。证据映射返回 `exact`、`cover` 或 `synthetic` 范围、来源行列及可选页码、段落与区域。宿主可通过 `ParsedDocument` 接入 PDF、Office、OCR 等解析结果，并维护原始二进制摘要。
- 持久化 `begin/append/status/list/publish/abort` 协议允许大文档分批准备表示，相同身份和批次内容可重试。批次顺序、摘要和根修订在发布前核对，最终事务原子安装新版本。
- 候选、解析归档和发布状态随检查点、WAL 及目录快照保存，重开后继续确认或终止上传。维度迁移前处理进行中的候选，已发布归档随目标事实保留。

协议、输入额度和示例见[文档解析与分批发布](../document-ingestion.md)。

### 命名图、共享成员与独立边

- 命名图拥有独立身份、Metadata 和修订，共享全库 NodeId，边唯一键包含 `(graph_id, src, dst, label)`。同一节点和同键边可分别参与多个图。
- 创建、替换、批量编辑和删除支持条件修订。修订包含创建 UUID 和递增计数，删除后重建获得新身份，冲突返回 `TDB_GRAPH_REVISION_MISMATCH`。
- 单图删除及成员移除清理所属关系，全库节点删除原子清理各图引用并推进相关修订。混合节点／图事务使用同一预检与 WAL 提交边界。
- 显式作用域支持单图、联合和出边遍历，联合节点去重，跨图独立边保留身份并稳定排序。Rust Reader、Python `graph_request`、Node `graphRequest` 使用同一事实与预算契约。

身份、修订、容量及持久化条件见[命名图](../named-graphs.md)。

### 文档与命名图统一 TQL／Planner

- 新增 `DOCUMENTS` 来源，`operation` 可选 `search`、`search_vector`、`search_hybrid`，复用文档查询配置。每个命中成为一行，`_` 提供节点，`document` 提供来源修订、分组与组内排名、证据、词项窗口、两路分数及实际检索配置。
- 文档来源可连接 `WITH`、过滤、图扩展、重排、聚合和分页。行按命中分数及稳定 ID 排序，分组排名保存在元数据中，`similarity()`、`text_score()` 和 `document.score` 分别对应向量、文本及融合分数。
- 只读查询支持 `GRAPH {graph_ids: [...], include_default: false, expected_revisions: {...}}` 前缀。MATCH、OPTIONAL MATCH、路径、Expand 和图算法使用同一请求内拓扑视图，跨图同键边分别保留，边属性 `graph_id` 提供命名图身份，默认图该属性为 `null`。
- Cascades 区分文档文本、精确向量和 ANN 物理来源，图阶段使用所选图统计。`EXPLAIN` 提供来源配置、访问路径、图修订和作用域统计，`EXPLAIN ANALYZE` 执行相同管线并报告实际行数与算子观测。
- Prepared 支持来源配置中的标量参数叶节点，并保留必需参数目录、首个引用范围和结构化错误。AST、plan 和 execute 诊断使用原始查询的 UTF-8 字节范围，行列按 Unicode 标量计算。
- 图视图、文档、投影及返回阶段统一执行内存准入、预算和取消控制。MATCH／WITH 行数边界、RETURN 工作区持有及直接执行入口的控制传播同步加固。

> **使用提醒**　`GRAPH` 作用域约束图匹配与图算子。文档、文本、属性和向量来源按各自条件产生候选。请求内拓扑占用随所选图及 Metadata 规模增长。Rust 手工构造 `TqlQuery`／`EdgeView` 时分别补充 `graph_scope`／`graph_id`，默认使用 `None`。语法与组合示例见 [TQL 参考](../tql-reference.md)。

### QuIVer 压缩重排与冷热驻留

- 编码支持既有 `int8`、中心化 `centered_int8` 和 `centered_int4`，查询表示可选择 `fp32`、`int8`、`int4`。精度优先预设使用中心化 INT8 × FP32，紧凑优先使用中心化 INT4 × FP32，两者均支持 Hot／SSD 驻留。
- 编码、查询精度、驻留方式与 `cache_bytes` 独立配置。原始向量作为事实保存，Hot 模式将压缩行驻留内存，SSD 模式按需读取。Rust 提供通用配置、检索、统计及关闭入口，原 INT8 名称提供兼容入口，Python／Node 复用 `quiver_request`／`quiverRequest`。
- 中心化编码持久化共享均值、分组参数及完整重建范数，采用 QVSSD v2。codec 1 的 QVSSD v1 通过既有解码路径读取，目录、来源、编码、行身份、slot、墓碑和 CRC 按相应阶段校验，覆盖任意尾维度。
- `use_for_ann` 显式启用普通 ANN 路径的压缩重排，TQL 向量来源标注 Approximate 分数。默认原始向量重排按既有查询配置执行。
- 数据库 Reader 按代际共享主 QuIVer 路由，使用固定工作区流式校验热区，减少重复路由和解码峰值。`routing_shared` 统计说明路由来源，主路由及 ID／slot 映射统一计入数据库基础堆，独立 Reader 管理自己的路由。
- 完整最终候选预取使用至多 64 行的有界批次，合并相邻记录及重叠窗口。I/O 批量与评分 SIMD 独立派发，完整组在 x86_64 使用 AVX2，尾组和其他平台采用标量评分。
- 有效持久图路由快照在打开时恢复，校验结果在本次打开流程复用，冷向量页在扫描后按平台机制回收，减少重复初始化及无效驻留。

> **使用提醒**　压缩重排使用近似余弦分数，召回率与阈值按业务数据及配置验证。只读配置需要已存在且来源与编码匹配的派生制品。FP16 查询表示属于后续工作。配置字段、预设示例和预算见 [QuIVer](../quiver.md)。

### SSD I/O、缓存与关闭边界

- `.qssd` 以来源摘要及发布 UUID 绑定事实代际，发布使用独占临时文件、同步、原子替换及父目录同步。旧 Reader 持有原代际句柄，失败按提交点返回 `not_committed` 或 `unknown`。
- Ready LRU 缓存按字节调容，同一行 Pending 合并，独立行租约持有内容及预算。缩容、切换和关闭归还各自拥有的资源，仍存活的行租约保留对应内容与额度。
- Windows 使用 OVERLAPPED／NO_BUFFERING，Linux 使用 O_DIRECT 与内核 AIO，按实际扇区及文件系统约束对齐。能力查询受限时采用 64 KiB 保守探测，每后端复用至多 64 KiB 读取窗口，统计报告实际后端、读取量、对齐及复用。
- Hot 预热、SSD 切换、构建及 checkpoint 刷新先准入过渡峰值，失败保留可用状态并支持重试。Hot 完成后释放异步 I/O 后端，切回 SSD 重新准入。
- 有界队列在取消、失败和关闭时排空原生 I/O 并 join 工作线程，线程与 CPU 池共享 Runtime 上限。发布候选使用 OS 租约，可写操作回收已退出发布者的暂存文件。

### 文档 ANN 与压缩运行时

- 文档向量和混合查询增加 `rerank="compressed"`，复用上述编码、查询精度、Hot／SSD 和缓存配置。默认 `original`，文档请求独立选择压缩模式。
- 来源、字段、元数据、成员及位置条件先约束候选，再预取及评分。候选扩展按文档组覆盖目标执行，精确与 ANN 路径保留各自路由、评分数量、导航访问及停止原因。
- 混合查询采用 RRF，保留文本、向量分数及两路排名。`retrieval.rerank` 与可空 `retrieval.compression` 返回实际重排、编码、查询精度和驻留信息，证据直接衔接来源引用。
- 文档和 Reader 工作区合并计量，向量更新按事实刷新压缩代际，预算拒绝、读取失败及取消归还临时额度。

> **使用提醒**　压缩文档检索要求已配置的浮点 ANN 运行时，`exact` 与压缩重排的组合返回 `TDB_INVALID_INPUT`。重开后重新配置运行时。接口示例见[文档向量与混合召回](../documents.md#文档向量与混合召回)。

### SDK、错误、事务与生命周期加固

- SDK 负责共享句柄、请求借用、语言转换及错误传播，存储内核负责 WAL、锁顺序、恢复、排空和文件释放。同库重复持有、回调重入及跨线程争用通过稳定错误返回，事务在准入拒绝后保留缓冲以供重试。
- Rust、Python、Node 和 Server 统一错误码、字段定位、`schema_version`、`stage` 与写入完成点。构造器、CRUD、检索、图、文本、索引、Prepared 和包装对象补充参数及成员路径诊断，保留宿主异常和原始错误链。
- `RequestContext` 在类型化调用、原生工作线程及自定义桥接间传播请求 ID、取消和期限。清理按资源所有权执行，请求退出与传输交付各自报告完成状态。
- Console 一致编辑快照与版本保护事务共享内核锁，有界持久回执通过完整原请求支持跨重开确认。冲突、幂等身份失配及未知写入结果保留结构化状态，宿主通过状态和事实确认结果。
- 关闭排空前后台任务及实际 I/O，释放 Windows mmap、文件、Hook 和实例额度。保留的关闭对象、快照和行租约按各自所有权管理资源，数据库路径在相关资源释放后可重新使用。
- 并行验收中的文档、预算、取消和 SSD 用例采用独立 `ResourceRuntime`，资源断言核对当前实例账本，覆盖拒绝后的完整结果及重试。

协议与操作见[内核 SDK](../kernel-sdk.md)、[公共错误契约](../error-contracts.md)、[嵌入式 Console](../embedded-console.md)和[关闭、快照与恢复](../lifecycle-snapshots.md)。

### Python 与 Node 绑定模块化

- Rust 绑定分别组织到 `src/bindings/python/`、`src/bindings/nodejs/`，按参数、错误、请求、运行时、数据库、记录、检索、图、文本、索引、TQL、事务、Hook、维护、生命周期及快照拆分，入口负责装配和兼容导出。
- Python 使用 PyO3 `multiple-pymethods` 分开登记类方法。Node 集中登记 `TriviumDB` 类名，使 napi-rs 2 多实现块共同组成原生构造器和方法集合，批量任务及 Hook 引用清理分别维护。
- Python 存根生成器、`.pyi`、npm `.d.ts`、类型消费和实际安装制品同步维护。安装 wheel 与 npm tarball 核对公共名称、签名、返回值及生命周期契约。

### 格式、升级与备份

当前主文件为 `.tdb` v13，WAL 为 v6，保存文档候选、解析归档、命名图及有界编辑回执。主文件支持 v5–v13 读取，历史 WAL 通过对应解码器恢复。QuIVer 及其他派生 sidecar 按自身版本解释，中心化 `.qssd` 使用 QVSSD v2。

1. 升级前停止写入并完成关闭，备份主文件、WAL、sidecar、manifest 及相关文件组成的完整文件组。
2. 使用 `0.9.1` Writer 打开需要恢复的数据库并完成 checkpoint，随后按业务需要配置压缩运行时。
3. ReadOnly／Immutable 按物理零写契约使用现有制品，需要生成派生索引时先通过可写实例准备。
4. 恢复时保持文件组代际一致，派生 `.qssd` 可从匹配事实重建。切回旧内核使用升级前备份。

### Installation and release channels

`0.9.1` is a stable release, combining the capabilities of `0.9.1-beta.1` with compressed reranking, document ANN integration, unified queries, and modular bindings. Rust Embedded Core implements storage, transactions, queries, recovery, and lifecycle semantics for Python, Node, CLI, and Server callers.

The Rust crate, CLI, Server source, npm package, and Python package use `0.9.1`. Python supports 3.9–3.12, npm uses `latest`, and Git tag `v0.9.1` identifies the validated Release merge commit. Server and WebUI retain their nightly development and compatibility boundaries.

```bash
cargo add triviumdb@0.9.1
pip install "triviumdb==0.9.1"
npm install triviumdb@0.9.1
```

### Document identity, structure, and evidence

- Document roots store source identity, content, hashes, and revisions. Structural manifests describe UTF-8 ranges, parents, and optional node representations for words, lines, paragraphs, and other blocks. Structural nodes can omit vectors, while vector representations follow database dimensions and dtype.
- Atomic writes install roots, representation nodes, and structural edges together, validating ownership, ranges, hierarchy, and expected revisions. Replacement, deletion, and recovery use existing transactions, WAL, and file-group publication, with structured conflict errors.
- Whole-document and fragment BM25 corpora support stable source grouping, block-kind field weights, root and fragment metadata filters, array membership intersections/unions, and source restrictions. Results include revisions, ranks, original byte ranges, and line/column evidence.
- Positional indexes support terms, phrases, and ordered proximity with the `tdb-text-ascii-cjk2-v1` analyzer. Repeated terms, overlapping CJK bigrams, Unicode casing, and multiline ranges follow one positional contract.
- Context requests validate revisions in one read view, expand neighbors and structural ancestors, and merge adjacent or overlapping ranges. Derived indexes build on demand and invalidate after fact changes, with budgets and cancellation for workspaces, positional visits, and output.

See [document sources and structure](../documents.md) for the full contract.

### Parsing, source mapping, and staged publication

- Built-in parsers handle plain text, Markdown, HTML, JSON, and JSONL. Explicit format, media type, or extension selects a parser, producing stable configuration identity and UTF-8 logical blocks, with bounded leaf splitting and optional line blocks.
- Parsed and source text have separate SHA-256 hashes. Evidence maps return `exact`, `cover`, or `synthetic` source ranges, line/column information, and optional page, paragraph, and region data. Hosts submit PDF, Office, and OCR results through `ParsedDocument` and maintain the original binary hash.
- Durable `begin/append/status/list/publish/abort` operations prepare large documents in batches. Identical identities and batch contents support retries. Order, hashes, and root revisions are checked before a final atomic transaction installs the version.
- Candidates, parsed archives, and publication state survive checkpoints, WAL recovery, and directory snapshots. Uploads can be inspected or aborted after reopening. Resolve active candidates before dimension migration, with published archives retained in target facts.

See [document ingestion](../document-ingestion.md) for protocols, limits, and examples.

### Named graphs, shared members, and independent edges

- Named graphs have their own identity, metadata, and revision, share database-wide NodeIds, and identify edges by `(graph_id, src, dst, label)`. Nodes and same-key edges participate independently in multiple graphs.
- Creation, replacement, batch editing, and deletion support revision conditions. Revisions combine a creation UUID and monotonic counter, recreation receives a new identity, and conflicts return `TDB_GRAPH_REVISION_MISMATCH`.
- Removing a graph or membership clears its relationships. Deleting a global node atomically clears references across graphs and advances revisions. Mixed node/graph transactions share preflight and WAL boundaries.
- Explicit scopes support individual graphs, unions, and outgoing traversal. Union nodes deduplicate while independent edges retain identity and stable ordering. Rust Reader, Python `graph_request`, and Node `graphRequest` use the same facts and budgets.

See [named graphs](../named-graphs.md) for identity, revisions, capacity, and persistence.

### Unified document and named-graph TQL/Planner

- The new `DOCUMENTS` source accepts `search`, `search_vector`, or `search_hybrid` with existing document options. Each hit produces a row containing node `_` and `document` metadata with source revision, group and hit ranks, evidence, term windows, component scores, and actual retrieval settings.
- Document sources compose with `WITH`, filters, graph expansion, reranking, aggregation, and pagination. Rows sort by hit score with stable ID ties, while metadata preserves group ranks. `similarity()`, `text_score()`, and `document.score` expose vector, text, and fusion scores respectively.
- Read-only queries accept `GRAPH {graph_ids: [...], include_default: false, expected_revisions: {...}}`. MATCH, OPTIONAL MATCH, paths, Expand, and graph algorithms share a request-owned topology view. Same-key edges remain distinct across graphs, and `graph_id` identifies named edges, with `null` for the default graph property.
- Cascades distinguishes text, exact-vector, and ANN document sources and plans graph stages using scoped statistics. `EXPLAIN` reports source settings, access paths, graph revisions, and scope statistics. `EXPLAIN ANALYZE` runs the same pipeline and reports observed rows and operators.
- Prepared queries support scalar parameter leaves in source configuration and preserve required parameter catalogs, first-reference locations, and structured errors. AST, plan, and execute diagnostics use original UTF-8 byte ranges and Unicode-scalar line/column positions.
- Graph views, documents, projections, and returned values share admission, budgets, and cancellation. MATCH/WITH row limits, RETURN workspace ownership, and direct-executor control propagation are hardened together.

> **Usage note**　`GRAPH` scopes graph matching and operators. Document, text, property, and vector sources generate candidates from their own conditions. Request topology memory grows with selected graphs and metadata. Rust struct literals for `TqlQuery` and `EdgeView` require `graph_scope` and `graph_id`, using `None` for defaults. See the [TQL reference](../tql-reference.md) for syntax and composition.

### QuIVer compressed reranking and residency

- Encodings include existing `int8`, `centered_int8`, and `centered_int4`, with `fp32`, `int8`, or `int4` query representations. The accuracy preset uses centered INT8 × FP32, and compact uses centered INT4 × FP32. Both support Hot and SSD residency.
- Encoding, query precision, residency, and `cache_bytes` are independent settings. Original vectors remain facts, Hot retains compressed rows in memory, and SSD reads rows on demand. Rust exposes generic configuration, search, statistics, and close APIs with compatible INT8 aliases. Python and Node use `quiver_request` and `quiverRequest`.
- Centered encoding persists the shared mean, group parameters, and full reconstruction norm in QVSSD v2. Codec 1 QVSSD v1 uses its existing decoder. Directory, source, encoding, row identity, slot, tombstone, and CRC checks apply at relevant stages, including arbitrary tail dimensions.
- `use_for_ann` explicitly selects compressed reranking for ordinary ANN. TQL vector sources identify these scores as Approximate. Default original-vector reranking follows existing query settings.
- Database Readers share the primary QuIVer route by generation and validate the hot section with fixed streaming workspace, reducing duplicate routing and decoding peaks. `routing_shared` identifies ownership, with primary routing and ID/slot mappings accounted in the database base heap. Independent Readers own their routes.
- Complete final-candidate prefetch uses bounded batches of up to 64 rows and coalesces adjacent records and overlapping windows. I/O batching and scoring SIMD dispatch are independent. Full groups use AVX2 on x86_64, with scalar tails and other-platform scoring.
- Valid persisted routing snapshots restore during opening, validation is reused within that opening operation, and scanned cold-vector pages are reclaimed using platform mechanisms, reducing repeated initialization and unnecessary residency.

> **Usage note**　Compressed reranking produces approximate cosine scores. Validate recall and thresholds against application data and settings. Read-only configuration requires matching existing artifacts. FP16 query representation is future work. See [QuIVer](../quiver.md) for fields, presets, and budgets.

### SSD I/O, caching, and shutdown

- `.qssd` binds facts to a source digest and publication UUID. Publication uses exclusive temporary files, synchronization, atomic replacement, and directory synchronization. Existing Readers retain generation-specific handles. Failures report `not_committed` or `unknown` according to the commit point.
- Ready LRU resizing is byte-based, Pending reads for one row coalesce, and independent row leases retain content and budget. Resizing, transitions, and closure release owned resources, while live leases retain corresponding content and accounting.
- Windows uses OVERLAPPED/NO_BUFFERING and Linux uses O_DIRECT with kernel AIO, aligned to actual storage and filesystem constraints. Limited capability discovery uses a conservative 64 KiB probe. Each backend reuses up to a 64 KiB read window, reporting actual backends, reads, alignment, and reuse.
- Hot warming, SSD transitions, builds, and checkpoint refreshes admit transitional peaks before starting. Failures preserve usable state and support retries. Hot completion releases asynchronous I/O backends, and SSD transitions readmit them.
- Bounded queues drain native I/O and join workers after cancellation, failures, and closure. I/O and CPU pools share Runtime thread limits. Publisher candidates use OS leases so writable operations can reclaim staging files from exited publishers.

### Compressed document ANN

- Document vector and hybrid queries accept `rerank="compressed"`, reusing encoding, query precision, Hot/SSD, and cache settings. `original` is the default, and document requests select their mode independently.
- Source, field, metadata, membership, and positional conditions constrain candidates before prefetch and scoring. Expansion targets document-group coverage. Exact and ANN paths report routes, scoring counts, navigation visits, and stop reasons.
- Hybrid retrieval uses RRF and retains component scores and ranks. `retrieval.rerank` and nullable `retrieval.compression` report actual reranking, encoding, query precision, and residency, with evidence feeding citations.
- Document and Reader workspaces share accounting. Vector changes refresh compressed generations from facts. Budget failures, read errors, and cancellation return temporary resources.

> **Usage note**　Compressed document retrieval requires a configured floating-point ANN runtime. Combining `exact` with compressed reranking returns `TDB_INVALID_INPUT`. Configure the runtime after reopening. See [document vector and hybrid retrieval](../documents.md#文档向量与混合召回).

### SDK, errors, transactions, and lifecycle hardening

- SDK adapters own shared handles, request borrowing, language conversion, and error propagation. The storage kernel owns WAL, lock ordering, recovery, draining, and file release. Repeated ownership, callback reentry, and cross-thread contention return stable errors. Admission failures preserve transaction buffers for retry.
- Rust, Python, Node, and Server share error codes, field locations, `schema_version`, `stage`, and write completion states. Constructors, CRUD, retrieval, graphs, text, indexes, Prepared queries, and wrappers provide argument/member diagnostics while retaining host exceptions and original causes.
- `RequestContext` propagates identity, cancellation, and deadlines through typed calls, native workers, and custom bridges. Cleanup follows ownership, while request exit and transport delivery report their completion states.
- Console snapshots and version-guarded transactions share kernel locks. Bounded durable receipts support confirmation after reopening with the complete original request. Conflicts, idempotency mismatches, and unknown writes retain structured status for confirmation.
- Shutdown drains foreground/background tasks and real I/O, releasing Windows mmap, files, Hooks, and instance quotas. Retained closed objects, snapshots, and row leases follow their ownership contracts, enabling path reuse after the relevant resources release.
- Parallel document, budget, cancellation, and SSD validation uses isolated `ResourceRuntime` instances and checks their own ledgers, complete results, and retry behavior.

### Formats, upgrades, and backups

The current main file is `.tdb` v13 and WAL is v6, storing document candidates, parsed archives, named graphs, and bounded editing receipts. Main-file readers support v5–v13, while historical WAL uses corresponding decoders. Derived sidecars retain their own format versions, with centered `.qssd` using QVSSD v2.

1. Stop writes, close the database, and back up the complete file group, including the main file, WAL, sidecars, manifests, and related files.
2. Open databases requiring recovery with a `0.9.1` Writer, complete a checkpoint, and configure compressed runtimes as needed.
3. ReadOnly/Immutable use existing artifacts with physical zero-write semantics. Prepare derived indexes through a writable instance when needed.
4. Restore generation-consistent file groups. Derived `.qssd` can rebuild from matching facts. Use pre-upgrade backups when returning to an older kernel.
