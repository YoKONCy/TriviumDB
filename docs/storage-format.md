## 文件组

| 制品 | 内容与职责 |
| --- | --- |
| `<db>` | 主文件：节点身份、图、文档、命名图、编辑回执及检查点状态；Rom 同时内嵌向量与 Payload |
| `<db>.idx` | 统一索引容器，保存 QuIVer 及其绑定、登记正文与关键词、文本检查点绑定、属性索引定义与索引、图目录，以及可选的压缩重排制品与 Pelorus 配置和图映像 |
| `<db>.vec`、`<db>.pld.<generation>` | Mmap 模式的向量和 Payload 事实 |
| `<db>.flush_ok` | Mmap 文件组的提交标记 |
| `<db>.wal`、`<db>.lock` | 事务恢复与实例租约 |
| `<db>.manifest.json` | 显式发布的 Immutable 代际或快照清单 |
| `<db>.publish` 及其备份 | 发布过程中保留旧代，用于中断恢复 |
| `<db>.migration` | 外部迁移目录提交后的确认标记；确认完成前普通 SDK 拒绝打开 |

正常检查点提交并清理完成后，原 `.quiver`、`.quiver.meta`、`.text`、`.text.meta`、`.pidx`、`.gidx`、`.qssd` 的内容集中在 `.idx`。写入阶段可以出现受发布协议管理的暂存组件，提交后由内核清理。Rust、Python、Node、CLI 和 Server 共用存储内核的布局。

登记正文、关键词与属性索引定义具有持久化语义。恢复它们需要完整的容器内容；正文可能来自显式登记，与节点 Payload 字段独立。

> **文件操作提醒**：使用快照 API 复制完整数据库。手工删除 `.idx` 会同时删除其中的登记文本与索引定义；只复制主文件会遗漏文件组成员。

## 容器布局与身份

主文件格式标识为 `15`，头部长度为 110 字节。类型字段及其 CRC 保留，字节 `74..90` 保存 16 字节数据库身份，`90..106` 保存 16 字节检查点标识，`106..110` 保存扩展头 CRC。数据库创建时生成身份，检查点重写和快照复制保持数据库身份，每次检查点写入生成新的检查点标识，快照保留原标识。

格式 15 将普通文档、解析文档及片段标签统一为文档结构 2。格式 14 及更早来源由外部迁移工具转换，目标保留正文、范围、节点身份、文档修订与事务确认语义。

容器使用小端编码，格式标识为 `1`。固定头部长度为 512 字节，各组件起点按 64 KiB 对齐，便于 Windows 映射和原生 Direct I/O 读取。

| 字节范围 | 字段 |
| --- | --- |
| `0..8` | 魔数 `TDBINDEX` |
| `8..16` | 容器格式标识、头部长度，各为 u32 |
| `16..28` | 主文件长度 u64、主文件 CRC32 |
| `28..32` | 保留字段 |
| `32..256` | 七个固定目录项，每项 32 字节 |
| `256..272` | 数据库身份 |
| `272..288` | 检查点标识 |
| `288..352` | Pelorus 配置与图映像的可选目录项，每项 32 字节 |
| `352..508` | 保留字段 |
| `508..512` | 头部 CRC32 |

目录顺序为 QuIVer、QuIVer 绑定、文本、文本绑定、属性索引、图目录、压缩重排、Pelorus 配置、Pelorus 图映像。每项记录组件编号、偏移、长度及 CRC32，空项全部为零。解析检查整数溢出、文件边界、非重叠范围、对齐、配对组件和保留字段。组件自身继续验证 dtype、维度、事实身份及各自内容布局。

普通打开验证数据库身份、检查点标识与主文件绑定；已加载组件按其解码与校验规则检查。延迟文本和 SSD 冷页沿各自访问契约读取，打开阶段按需加载。快照校验额外核对完整容器的长度与摘要。

> **格式提醒**：软件版本、磁盘格式身份和检查点代际分别维护。当前改造完成物理容器统一；本次收敛以 SDK 层冻结为目标，内部布局继续按明确格式身份演进。`1.0.0` 再冻结内核正式接口与持久化契约，详见[两阶段冻结目标](kernel-sdk.md#两阶段冻结目标)。

## 发布、恢复与资源

普通打开先取得已有协调租约，再校验可变文件头。租约随实例或后台关闭任务持有。主检查点缺失时，只有空文件组或单独的协调锁允许新建数据库。发现残存向量、Payload、索引、WAL 或其他保留制品时，打开返回错误并保留现场。带发布日志的文件组先按日志恢复，再执行相同的准入检查。

新建及重新发布的主检查点与 WAL 共用唯一封条，覆盖文本库和纯向量库。清理通过已同步的短日志原子替换原 WAL。进程中断后，旧日志或新日志均能定位已发布检查点。旧构建生成的当前格式库在下次完成检查点发布时取得新封条。

检查点先保留旧文件组，再写新组件与容器暂存文件。容器完成同步和原子替换后，Mmap 发布提交标记，Rom 发布日志提交状态。提交前失败按旧文件组恢复；提交后继续保留新代并清理旧组件。重开遇到已提交的待清理日志时，先校验完整容器和各组件，再清理恢复材料；校验失败保留日志、备份和暂存组件。发布日志格式 `3` 将 `.idx` 纳入同一恢复组。

组件读取限定在目录指定范围内。属性索引和图目录直接映射容器范围；SSD Reader 将组件偏移加入实际文件偏移，缓存与异步读取继续按原公共配置工作。文件替换使用完整新文件，已有读取持有原文件句柄和映射。关闭排空读取后释放映射及文件资源，完成条件见[实例关闭](lifecycle-snapshots.md#资源释放完成点)。

当前 Mmap 检查点标记为 81 字节，对外置 Payload 使用独立的 SHA-256。历史 53 字节标记可直接读取，首次完成新检查点后采用当前标记。代际清单现在对所有声明文件记录 SHA-256，旧清单继续按原摘要验证。

容器发布按固定大小缓冲流式复制组件，并同时计算校验。检查点和压缩编码更新会重写完整容器，包括需要保留的 SSD 组件；宿主应为候选容器、旧代备份及暂存组件预留磁盘空间。

> **运行提醒**：ReadOnly 与 Immutable 保持物理零写。当前格式容器缺失、身份错配或目录损坏返回结构化错误；损坏的登记正文与索引定义按事实完整性要求处理。显式文本重建入口接受宿主提供的完整正文和关键词。

## 备份与格式演进

`create_snapshot`、`verify_snapshot`、`restore_snapshot` 使用统一制品目录，快照包含整个 `.idx`，包括已发布的压缩重排组件。恢复后按原 dtype、维度与访问模式打开；压缩运行时配置继续核对来源身份。

CLI JSONL 用于节点和默认图边的数据交换。完整备份使用快照。自 SDK 冻结起，TDB 版本升级涉及的数据与制品迁移统一由外部脚本显式执行，覆盖文档、命名图、登记文本、索引定义及回执等完整事实；脚本可调用版本固定的专用迁移程序，负责预检、锁、验证、目标发布与报告。

正常打开只接受当前格式家族，包括主文件 15、WAL 7、发布日志 3、Mmap 标记 3、索引容器 1，以及当前组件布局。磁盘身份保留整数标识，用于识别来源和拒绝不匹配输入。已识别历史身份返回 `TDB_MIGRATION_REQUIRED`，未来身份返回对应不支持格式错误。

历史解码与来源恢复后端位于独立迁移 workspace，使用方式见[外部迁移工具](migration.md)。生产数据库读取要求绑定的 `.idx`，当前检查点及 SSD 更新沿各自明确的暂存组件入口发布。显式独立索引制品沿当前布局的独立读写入口使用。正常内核维护当前格式的往返、损坏拒绝、事务恢复、只读零写与资源释放。
