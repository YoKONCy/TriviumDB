# WebUI 验收边界

Server 与 WebUI 处于 nightly 快速迭代阶段。禁止新增或执行 UI/UX、样式、布局、视觉基线、动画及耗时阈值测试，也不得将其作为本地、CI、合并或发布门禁。不得以冒烟、行为、诊断或可选手动任务的名称绕过此规则。

界面方案可以随前端开发调整。GitHub Actions Runner 的机器性能与调度条件不同，不能通过固定等待、动画完成时长、输入延迟、帧率或渲染耗时判定功能是否通过。

## 适用检查

- 代码审查：核对请求体、版本前置条件、事务身份、状态所有权、失败恢复及数据是否可能被错误覆盖或重复写入。
- 静态语法检查：解析内嵌 JavaScript，检查语法错误，不启动浏览器，也不对 DOM、交互或样式作断言。
- Server 非 UI 契约：执行 `cargo test --locked -p triviumdb-server`，检查 HTTP、TQL、版本冲突、事务及幂等处理。断言依据结构化状态和实际数据，不以执行耗时作为正确性标准。
- Git 与文档检查：核对变更范围、链接及 `git diff --check`。

内核、SDK 和 CLI 继续执行各自适用的非 UI 验收。测试基础设施为避免进程无限挂起设置的超时上限，不是性能或体验指标，不得把“在某个固定时长内完成”作为产品正确性断言。

## CI 与历史工具

`.github/workflows/webui.yml` 仅保留 Server 非 UI 契约，不安装浏览器，不执行交互套件、页内自检、截图比对或视觉基线更新。

仓库既有浏览器脚本和页内自检保留为历史代码，不得运行或继续补充，也不作为当前验收入口。PR #85 不新增浏览器或页内 UI 用例。报告应明确实际执行的非 UI 检查，不将历史浏览器结果或已撤回的测试算作当前验收证据。

## 节点文档的事务边界

文档提交必须冻结实际发送的操作、请求体、前置条件和幂等键。结果不确定时保留整个原批次，以同一事务身份确认；单个节点内容相等不能证明混合事务已经完成。确认后的新草稿使用独立批次。

页面刷新或关闭会丢失内存中的原请求，恢复的正文草稿不是整笔事务的提交证明。草稿的数据库身份与服务端幂等缓存限制见[未发布变更](changes/unreleased.md)。
