## 一、产品定位

### 1.1 高维优先 + 维度全兼容

**既有成果与本次论文贡献边界（不可混淆）**：QuIVer 已作为独立工作发表于 VLDB，其 BQ2、Vamana 路径、冷热分离设计与纯向量检索性能都是 TriviumDB 已有成果和核心产品卖点。它在本次新论文中只作为已发表的向量检索底座、系统组件和实验基线，并规范引用既有论文；不得再次声称为本次创新，不得规划 QuIVer 单独投稿，也不得用“系统论文”重新包装其既有贡献。

**目标场景**：工业 RAG 主流负载，即 384 维以上文本 embedding，768–3072 维覆盖绝大多数生产系统。QuIVer 已有工作通过面向高维场景的设计提供强大的向量检索能力。

由此确立的定位约束：

- 所有 Gate 判据以高维为默认场景；低维只作兼容性验证。
- 只在 64 维小规模数据上得出的结论，不足以否决或确立任何算法路线。历史上曾险些因 64 维 1M 数据中 vector+property 慢 18% 而误判路径无效，根因是 64 维根本没有 page cache 悬崖。
- 维度全兼容：字节是唯一一等预算单位；无维度分档策略分支；384/768/1536/3072 参数化测试为硬性要求。

### 1.2 核心竞争力：原生业务图上的三模管线

TriviumDB 本身具备由既有 VLDB 工作 QuIVer 提供的强大纯向量检索能力，这是数据库的重要卖点；但本次新论文的差异化与新增贡献不在重复证明或重新包装 QuIVer，也不在属性过滤（赛道极度拥挤），而在：

> **基于原生统一索引和 SoA slot 寻址，在单一执行引擎内把向量检索/精排、属性索引、图遍历与图算法组合为有界、可优化、零拷贝候选传递的多阶段查询管线。**

支撑证据链（三重收敛）：

**证据一：文献空白只在图侧**

| 方向 | 竞争密度 |
|---|---|
| 向量 + 属性过滤 | 非常密集（每年 VLDB/SIGMOD 5–10 篇） |
| 向量 + 稀疏/文本 | 密集 |
| 向量 + 知识图遍历 | 稀疏（仅框架级 HMGI、工程级 TigerVector） |
| **向量 + 属性 + 原生业务图联合查询** | **空白** |

**证据二：实验数据指向图**

混合查询实验中唯一产生稳定正收益的就是图通道（图候选并集 P95 约 7–10×）；属性信号在导航层从未证明价值。

**证据三：架构独有优势**

| 系统 | 跨模组合代价 |
|---|---|
| Neo4j + 外部向量库 | 跨系统传 ID、网络往返与序列化 |
| Qdrant / Milvus | 无原生业务图，图算法外置 |
| Kùzu / NaviX | 图向量同库，但查询路径以固定策略为主 |
| **TDB** | **SoA 同进程、同 mmap、NodeId↔slot 直接寻址，算子间零拷贝候选传递** |

### 1.3 主张的演进与收敛

原始假设（C1 立项时）：三信号线性加权单队列联合导航。
当前主张（C1.6 完成后）：三模算子代数 + 跨阶段 Planner + 原生图算法自由组合。

收敛过程：C1 实验否证了导航层融合 → 发现图候选并集才是真实收益 → C1.5 将其 Planner 化 → C1.6 发现真正的架构机会是「任意组合的算子代数」而非「单一联合导航」→ C1.6/C1.7 完成后主张定型。

关键认知：**「图能力停留在单锚点 1/depth」时代的任何加速本质上都只是 candidate union，审稿人会正确指出这一点。** 因此 C1.6 把图能力升级为多锚点、路径权重、路径条数、结构统计、子集化图算法与标准 Leiden，并全部算子化进入管线。

### 1.4 TSNG 名称与角色澄清（重要）

TSNG（Tri-Signal Navigation Graph）是立项时的名称，指「三信号联合导航图索引」。经过 C1 否证与 C1.6 重构后，代码中 `tsng.rs` 的实际内容是：

- 六条混合搜索 AccessPath 的执行策略层（`IndustrialAccessPath`）。
- 查询内存预算与观测指标。
- exact ground truth 与质量指标。

它**没有**自己的持久化结构、导航拓扑或构建过程——不是索引。真正落盘的索引是 QuIVer（`.vidx`）、属性索引（`.pidx v4`）、图索引（`.gidx v2`）。

| 问题 | 现状 | 处理 |
|---|---|---|
| TSNG 是索引吗 | 否，是执行策略层 | 论文与文档统一表述 |
| 名称会误导吗 | 会（`bench_tsng_*`、`src/tsng.rs` 暗示索引） | 投稿前按 §5.5 清理 |
| 要改代码名吗 | 可选 | 低风险方案：仅统一文档表述；中风险：`tsng.rs` → `hybrid_search.rs` |
| TSNG 概念还保留吗 | 保留为「工业混合搜索」的品牌名 | 不再主张图结构创新 |

### 1.5 目标用户与查询故事

| 用户 | 典型查询 | 管线表达 |
|---|---|---|
| RAG / Agent 记忆检索 | 「找与当前任务语义相似、状态活跃、且被同伴引用过的记忆」 | SEARCH → EXPAND → similarity > θ → RANK（Q2） |
| 推荐系统 | 「种子用户的 2 跳社交圈中，向量相近且同社区的 top 代表」 | SEARCH → EXPAND → Leiden → 每簇 top-1 → RANK（Q7） |
| 知识图谱问答 | 「锚点实体可达、类型匹配、向量最近的实体」 | FIND → EXPAND → RANK（Q5） |
| 风控/反欺诈 | 「与可疑账户共享社区且中心性高的账户」 | SEARCH → WCC → 分量过滤 → RANK（Q11） |
| 迭代扩散 | 「从种子出发不断扩展相似节点直到收敛」 | ITERATE（Q14） |

共同点：**没有任何一个能被「向量库 + 后过滤」或「图库 + 外部向量」单系统优雅表达**——这正是产品定位的落点。

### 1.7 嵌入式定位的含义

TDB 是嵌入式数据库（类 SQLite 形态），不是服务端数据库（类 PostgreSQL 形态）。这一定位影响一系列设计取舍：

| 维度 | 嵌入式取舍 | 放弃了什么 |
|---|---|---|
| 部署 | 单文件数据库 + sidecar，进程内链接 | 无网络协议、连接池、多租户隔离 |
| 并发 | 多读单写 + 查询内并行 | 无服务端并发写仲裁 |
| 内存 | 进程内共享 mmap，无跨进程拷贝 | 无法独立扩缩容 |
| 安全边界 | 由宿主应用决定（文件权限/加密） | 无内置鉴权层 |
| 语言绑定 | Rust 核心 + Python/Node 绑定 | 无独立客户端 SDK 生态 |

嵌入式与三模管线的协同：Agent/RAG 应用（主要目标场景）恰恰需要「进程内零往返的复杂查询」——跨系统编排的序列化开销在每次 EXPAND/RANK 间都会放大，嵌入式是管线性能主张成立的前提。

对应的非目标（§九）：分布式分片、服务端形态都被此定位排除。

### 2.4 演进决策日志（关键转折点存档）

按时间序记录塑造当前路线的决策；每条含「当时的选项、选择、依据」。

**决策 1：A2 先 BTreeMap 后 ART（两阶段）**

- 选项：直接写 ART / 先 BTreeMap 冻结语义。
- 选择：后者。
- 依据：语义与接口先稳定，ART 作为可替换实现用 100K 随机操作 differential 验证等价；ART 首版比 BTreeMap 慢（108.8 vs 78.2 ms 构建）但没有阻塞语义交付。

**决策 2：C1 失败后转向 Planner 并集而非继续调参**

- 选项：继续调 scorer 权重/限幅 / 转向 Planner 路径选择。
- 选择：后者。
- 依据：三组实验（线性/限幅/双队列）一致显示属性侧无收益，最优 cap=0% 说明继续调参无意义；图候选并集 ~9.7× 的收益真实存在且可工程化。

**决策 3：确立「高维优先」并重写 C2 判据**

- 选项：保留以 P95 线性退化为判据 / 改为页读取悬崖判据。
- 选择：后者。
- 依据：64 维 100K 候选仅 25.6 MB（无悬崖），768 维 307 MB、3072 维 1.23 GB（必有悬崖）；判据错则结论全错。

**决策 4：C1.6 从「增强图信号」重构为「三模算子管线」**

- 选项：继续增强 `GraphSignalQuery` / 建立可组合算子代数。
- 选择：后者。
- 依据：使用者按业务逻辑任意串联三模能力，组合空间数百种；单点增强无法覆盖，枚举 API 不可维护。单锚点 1/depth 的「图能力」会被正确归约为 candidate union。

**决策 5：属性侧降级为工程能力，不再作为创新点**

- 依据：文献赛道每年 5–10 篇；实验无导航层收益；工程上 C1.5 已足够好。C2 因此降为条件性任务。

**决策 6：C1.7 并行先做低风险算子，图算法第二批**

- 依据：多源 EXPAND/rerank/Degree/扫描只需确定性归并；单源 BFS/PageRank/WCC 需要原子 bitmap、双缓冲专项设计，混在一起风险高。

**决策 7：标准 Leiden 替换历史标签传播**

- 依据：历史 `run_leiden` 实为标签传播，若被审稿人或用户发现名实不符，损害全部图算法可信度；标准实现后函数名与语义统一。

**决策 8：benchmark 按能力重组，删除阶段命名**

- 依据：`bench_c1_5_1_*` 等名称对外部使用者无意义且暴露内部过程；重组为 `bench_indexes_and_leiden`、`bench_pipeline_gate` 等能力名，历史 alias 全部删除。

### 3.1 最接近的 8 篇工作

#### Allan-Poe（浙大 + 华为，PVLDB 2026 Vol.19）— ⚠️ 最近竞争者

- dense + sparse + full-text 三路径融进单一图索引，构图混合距离，查询动态调权，GPU 加速。
- 差异：三条路径都是**检索信号**，不含原生数据图拓扑；其「图」是 ANN 导航图；无 BQ 廉价信号；依赖 GPU。
- 威胁：若该团队加入知识图拓扑，直接与本文方向竞争。arXiv:2511.00855v2。

#### NaviX（Waterloo，PVLDB 2025 Vol.18 No.11）— 威胁低

- Kùzu 中原生 HNSW，遍历中按局部选择性自适应选择 pre/post-filter。
- 差异：图为 ANN 导航图；属性过滤是遍历时检查不参与导航评分；磁盘索引方向。

#### SIEVE（ByteDance + UIUC，PVLDB 2025）— 威胁低

- 为不同谓词建多个子索引，查询时分析模型选最优。
- 差异：空间换时间，不改遍历策略；只处理 label 级离散属性。

#### Compass（CUHK，arXiv → PVLDB 2026）— 威胁低，互补

- 统一协调 HNSW/IVF 与 B+Tree 做联合查询执行，支持任意 conjunction/disjunction/range。
- 差异：查询执行层协调，不修改向量索引内部遍历；不涉及图拓扑。

#### DEG（NTU，SIGMOD 2025）— 威胁低

- 双模态向量（image+text）动态边导航图，边带 active range 按查询 α 启停。
- 差异：两个模态都是向量；无属性过滤、无图拓扑。

#### HMGI（清华 BNRIST，arXiv 2025.10）— 威胁低

- Neo4j 上融合图遍历与 ANNS 的框架级 proposal。
- 差异：向量与图仍是两个独立步骤；未实现单遍历融合；完成度不足。

#### Filtered-DiskANN（Microsoft Research）— 路线不兼容

- FilteredVamana 让过滤标签参与 RobustPrune 选边；StitchedVamana 分标签建子图再缝合。
- 关键分歧：其全部收益来源是**标签介入建图**，直接违反 TDB 底线「元数据不得参与或主导 Vamana 建图建边」。不可移植。
- 血缘：QuIVer 与 DiskANN 同源于 Vamana，但 QuIVer 走 BQ2 原生 + 冷热分离 + 多层贪心下降，DiskANN 走 PQ + 磁盘页。

#### SAP Tri-Modal Fusion（arXiv 2025.06）— 威胁低

- dense + BM25 + graph embedding 拼成统一向量 + LLM rerank。
- 差异：图信号被编码成 embedding，丢失原生拓扑（不能沿实际边遍历）。

## 四、已否证路线的结论存档

> 本节一笔带过，只保留结论与教训；完整过程数据见旧版 roadmap §五 与旧版 plan §21.9–21.12。

### 4.1 C1 单队列三信号导航（❌ 否证）

| 策略 | 属性 | 图 | 三信号 |
|---|---|---|---|
| 线性加权单队列 | ❌ | ❌ | ❌ |
| Bounded Bonus 限幅 | ❌ 最优 cap=0% | ❌ | ❌ 最优 cap=0% |
| 双队列 + 图 seed | ❌ | ✅ 3.93× | ✅ 2.29× |
| 图候选直接并集 | — | ✅ ~9.7× | ✅ ~7.4× |

三条定论：

1. 元数据 bonus 会把 beam 拉向「属性正确但向量簇错误」的区域；属性信号在导航层无价值。
2. 图场景收益来自图候选直接进候选集，不是沿 Vamana 扩展。
3. 正确方向是 Planner 化的候选并集 → 已由 C1.5 落地并验证。

保留资产：C0 ground truth、Matched-Recall Gate 框架、固定相关性数据集继续作为评测基座；双队列/图 seed 保留为默认关闭实验 API。

### 4.2 C3 多信号构图（🧊 冻结）

前置 C2 通过；约束（不改原始图、独立 overlay、纯向量只走原图）把收益空间压缩到很小，而 Filtered-DiskANN 证明的收益来源恰被底线禁止。属性信号导航层已被否证，构图期再试先验概率低。

### 4.3 教训固化

- 单点算法创新（scorer 调权）输给系统级创新（Planner 路由）——这本身塑造了后续所有决策。
- 负面结果保留价值：C1 的否证直接指出了正确方向，且成为论文中解释路线选择的依据。
- 数据集与 Gate 一经运行即冻结，不为算法改数据。

### 4.4 C1 实验的完整对照表（紧凑版）

100K、64 维、可控相关性数据（32 簇，属性 5.024%、图边 4.992% 选择性），Matched-Recall Gate（同 Recall@10 ≥ 0.80 下比 P95）：

| 策略 | 向量+属性 | 向量+图 | 三信号 |
|---|---|---|---|
| Post-filter 基线（ef=2048） | 2.759 ms | 2.726 ms | 3.123 ms |
| 线性单队列 | 10.423 ms（0.27×） | 3.450 ms（0.79×） | 11.338 ms（0.28×） |
| Bounded Bonus | 最优 cap=0% | cap=10% 无观测变化 | 最优 cap=0% |
| 双队列+图 seed | 7.134 ms（0.42×） | **0.752 ms（4.19×）** | **1.329 ms（2.33×）** |
| 图候选直接并集 | — | **0.326 ms（8.4×+）** | **0.416 ms（7.5×+）** |

结论一目了然：导航层改造全部劣于基线；候选集层的图并集全面胜出。这是「从导航创新转向执行层创新」的数据基础。

### 5.2 主攻方向

**「三模算子管线 + 原生图算法组合」论文（VLDB/SIGMOD Research）。**

创新点：

1. **三模算子代数**：NodeSet 统一候选交换格式 + 命名分数列 + provenance；任意算子可组合。
2. **跨阶段 Planner**：Cascades Memo 在完整管线上优化（下推/融合/合并），确定性计划选择，字节预算按阶段切片。
3. **原生图算法自由组合**：PageRank/WCC/betweenness/degree/标准 Leiden/SA-PPR/ALL_PATHS/ITERATE 全部子集化（INDUCED/EXPAND/BOUNDARY 三态语义）进入管线。
4. **工程不变量**：确定性（并行线程矩阵逐位一致）、预算 fail-closed、ReadOnly/Immutable 零写、维度全兼容。

明确**不是本次创新点的**：QuIVer 的 BQ2、Vamana 路径、冷热分离与纯向量性能——这些均属于已发表的 VLDB 工作，本次只引用并作为底座；属性过滤属于拥挤赛道中的工程能力。

```text

   7.4 跨阶段优化收益分解（候选缩减 / 页读取 / P95）
   7.5 消融（去掉 Planner / 去掉图算子 / 去掉并行）

   7.7 参数敏感性（top-K、跳数、选择性、维度）
8. Negative Results（诚实章节）

10. Conclusion
```

与旧版骨架的本质区别：旧版第 4–5 章（Tri-Score Navigation、Joint Lower-Bound Pruning、soundness 证明）对应的是未建成的联合导航索引；新版第 3–6 章对应的是已通过 16 点 Gate 的真实系统。

### 5.3.1 预期审稿问题与回答（Q&A 准备）

| 预期问题 | 回答要点 |
|---|---|
| 「这不就是把算子串起来？数据库早就有了」 | 区别在三模统一交换格式（NodeSet 带命名分数列与 provenance）、近似/精确分数的类型安全、以及跨阶段而非单阶段的优化；现有系统没有把图算法当查询算子 |
| 「为什么不用 GraphRAG pipeline 编排」 | 跨系统传 ID 的序列化/往返成本；无统一预算与优化；无 matched-result 保证 |
| 「Cascades 是现有技术」 | 承认；贡献不在优化器框架，在「跨阶段 + 三模成本模型 + 安全规则集」的集成与实证 |
| 「Recall 怎么保证」 | exact rerank 强制插入规则；近似分数不得用于精确谓词；differential 全量对照 |
| 「图算法结果对子集敏感」 | INDUCED/EXPAND/BOUNDARY 三态显式语义；质量标记进 ScoreKind |
| 「和 Allan-Poe 比」 | 其融合的是三种检索信号、图为 ANN 导航图、GPU；本文含原生数据图拓扑、CPU/mmap |
| 「和 Compass 比」 | 其为执行层协调、不改索引内部；本文算子级融合 + 图算法 |
| 「可复现性」 | 固定 seed 确定性数据；逐位确定性并行；benchmark 入口与环境变量公开 |
| 「为什么属性导航失败还要写」 | 负面结果塑造了路线选择，是方法论贡献的一部分 |

## 九、非目标（当前不做）

| 非目标 | 理由 |
|---|---|
| 完整 LSM-Tree 存储引擎 | 现有 WAL + delta + generation 已满足嵌入式负载；LSM 引入压缩/合并线程与 SSD 写放大，违反低磨损约束 |
| 页式 B+Tree | 已选 ART；页管理与 mmap 不可变块模型不匹配 |
| 2-Hop Labeling / Transitive Closure | 构建与更新成本过高，与动态负载冲突 |
| RDF SPO 六向索引 | TDB 不是 RDF 数据库；业务图场景不需要 |
| 分布式索引分片 | 嵌入式定位；分布式是另一个产品形态（也超出当前人力） |
| GPU 加速索引 | Allan-Poe 已占 GPU 赛道；TDB 差异化在 CPU/mmap 嵌入式 |
| 标签参与 Vamana 建图 | Filtered-DiskANN 路线，违反纯向量零退化底线 |
| C3 多信号构图 | 前置 C2 未验证；约束压缩收益空间；属性导航已否证 |
| 查询语义改动（论文期间） | 冻结语义保证实验可比性；只加实验不改行为 |

每条非目标都可能在未来某个条件下重评估，但重评估必须先出现对应的真实需求或前提变化，而不是「顺手做」。

## 十三、术语与叙事速查

对外/论文用词统一表，避免同一概念多种叫法造成 reviewer 困惑：

| 概念 | 统一用词 | 避免用词 |

| 算子间交换格式 | NodeSet | 中间表、结果集（口语可用，论文不用） |
| 图算法子集语义 | INDUCED / EXPAND / BOUNDARY | 子图过滤、局部算法 |

## 十四、一页纸摘要

**这是什么**：TriviumDB（TDB），嵌入式三模数据库——向量（QuIVer ANN）、属性（四类持久化索引）、原生业务图（预算化遍历 + 8 类图算法算子）在同一进程、同一 mmap 内联合查询。

**核心主张**：三模算子管线。NodeSet 作为算子间唯一交换格式（候选集 + 命名分数列 + provenance），TQL `WITH` 链表达任意组合，Cascades 跨阶段优化，全程逐位确定性 + fail-closed 预算 + 只读零写。

**为什么成立**：

1. 文献空白：向量 + 属性 + 原生图拓扑的联合查询无直接同类（8 篇最近工作逐一对比）。
2. 实验支撑：四维度 16 点 Gate 全部 matched-result，候选减少 80–98.7%，P95 加速 6.38–179.84×。
3. 架构独占：嵌入式零往返 + slot 直址 + 零拷贝候选传递，是跨系统编排无法达到的。

**已否证并放弃**：三信号单队列导航（C1）——最优限幅为 0%，属性信号在导航层无价值；收益属于图候选并集，已 Planner 化（C1.5）。

**当前状态**：A/B 轨道、C1.5/C1.5.1、C1.6 管线、C1.7 并行、A3/A4/B3/标准 Leiden 全部完成并通过 Gate。v0.12 收尾。

**下一步**：v0.13 论文实验（外部数据集 + 竞品基线 + scalability），随后 arXiv 占位（窗口期 1–2 年）与 VLDB/SIGMOD 投稿。C2 只做条件性 Step A 实验；C3 冻结。

**文档导航**：定位/叙事/优先级 → 本文档；实现/接口/数据/测试 → 《TriviumDB 索引与三模管线工程实施方案》；benchmark 复现 → `benches/README.md`。

### 14.1 三十秒电梯陈述（备用）

> 「Neo4j 加向量插件、或者 Qdrant 外挂图算法，做不了'先向量检索、再沿业务图扩展、对结果跑社区发现、最后按相似度精排'这种查询——要么跨系统传 ID，要么固定死几种模式。TriviumDB 把向量、属性、原生图做成同一个嵌入式引擎里的可组合算子，TQL 一条 WITH 链表达任意组合，优化器跨阶段选计划，全程结果确定、预算可控、只读零写。四组代表性查询在四个维度上比朴素计划快 6 到 180 倍，结果逐字段一致。」
